# Distinguish a Deliberate Merge Decline From a Resolver Break in the Quarantine Metrics

<summary>
- A quarantined file's metric now records which resolver branch produced the quarantine, so a deliberate decline is separable from a resolver break.
- Operators can separate the two from `/metrics` alone, without reading pod logs.
- A new companion series counts quarantines by cause.
- The existing resolver-failure series stops lumping every vault-api fallback into one bucket.
- The cause set is a closed, typed set, so the label cannot grow without bound.
- Every new series is pre-initialised, so it reads as zero before the first event rather than as a missing series.
- The change is observability only: which conflicts quarantine, and how, is unchanged.
</summary>

<objective>
Make the quarantine metrics carry the distinction the log already makes, so an operator reading `/metrics` can tell a deliberate merge decline (vault-api refused the merge on purpose, carrying a `reason`) from a resolver break (the merge request failed), and can attribute each quarantine to the branch that produced it. Today all four vault-api branches arrive as the same `vault_api_failed` bucket and every quarantine is the same unlabelled count, so the first thing read on an incident cannot say which happened. The cause label enumerates every vault-api branch the log distinguishes, not only the two extremes; the YAML resolver's own failure categories continue to arrive as `other`.
</objective>

## 1. Add the typed cause set and the companion counter (`pkg/metrics/metrics.go`)

1.1 Add a typed cause set following the repo's `go-enum-type-pattern` convention (`type conflictKind int` in `pkg/git/git.go` is the in-repo precedent). These are the only legal values of the new label:

```go
// QuarantineCause is the closed set of reasons a conflicted file was quarantined
// during pull.
type QuarantineCause string

const (
	// QuarantineCauseDeclined is a deliberate decline: vault-api refused the
	// merge on purpose and returned a result other than "merged" with a reason.
	QuarantineCauseDeclined QuarantineCause = "declined"
	// QuarantineCauseBreak is a resolver break: the merge request itself failed
	// (transport error, non-200, unparseable response).
	QuarantineCauseBreak QuarantineCause = "break"
	// QuarantineCauseNoThreeSides is a conflict whose three sides could not be
	// read, so it is not a modify/modify merge: an add/add or delete/modify
	// conflict has no base stage, and a failed `git show`/`merge-base` also lands
	// here. It therefore cannot distinguish a base-less conflict from a git
	// failure; use the resolver-failure category for that.
	QuarantineCauseNoThreeSides QuarantineCause = "no_three_sides"
	// QuarantineCauseEmptyContent is a merge reported as merged but carrying no
	// content to stage.
	QuarantineCauseEmptyContent QuarantineCause = "empty_content"
	// QuarantineCauseOther covers every other path into quarantine: a write
	// failure, a git-add failure, or a resolver other than the vault-api one.
	QuarantineCauseOther QuarantineCause = "other"
)

// AvailableQuarantineCauses lists every QuarantineCause the cause label accepts.
// init() ranges over it to pre-initialise the series and tests range over it to
// assert the full set. Keep it in sync with the constants above.
var AvailableQuarantineCauses = []QuarantineCause{
	QuarantineCauseDeclined,
	QuarantineCauseBreak,
	QuarantineCauseNoThreeSides,
	QuarantineCauseEmptyContent,
	QuarantineCauseOther,
}
```

`String()` / `Validate()` / a plural collection type / `Contains()` are deliberately omitted: the value is never user-supplied and needs no membership validation. `conflictKind` (`pkg/git/git.go`) is the in-repo precedent for this minimal form.

1.2 Declare the counter next to `QuarantinedFilesTotal`:

```go
// AvailableQuarantineCauses and is never sourced from vault-api's free-text

	Name: "git_rest_quarantine_cause_total",
	Help: "Total files quarantined during pull, labelled by the resolver branch that caused the quarantine (declined=deliberate vault-api decline, break=merge request error, no_three_sides, empty_content, other).",

```

```go

	QuarantineCauseTotal.WithLabelValues(string(cause)).Add(0)
}
```

## 3. Carry the cause from the resolver to the quarantine (`pkg/git/vault_api_merge_resolver.go` and `pkg/git/git.go`)

3.1 In `pkg/git/vault_api_merge_resolver.go`, add a typed error that carries a cause and survives the `errors.Wrapf` that `Resolve` applies per path, plus one exported derivation so the cause can be read from outside the package (the resolver's own tests are external `package git_test`):

```go
// quarantineCauseError tags a resolver error with the branch that produced it,
// so the quarantine path can label the quarantine with its cause. It unwraps to
// the underlying error, so existing error handling is unchanged.
type quarantineCauseError struct {
	cause metrics.QuarantineCause
	err   error
}

func (e *quarantineCauseError) Error() string                          { return e.err.Error() }
func (e *quarantineCauseError) Unwrap() error                          { return e.err }
func (e *quarantineCauseError) QuarantineCause() metrics.QuarantineCause { return e.cause }

// withQuarantineCause tags err with cause. A nil err is returned unchanged, so
// a fallback that resolved the file is never wrapped.
func withQuarantineCause(err error, cause metrics.QuarantineCause) error {
	if err == nil {
		return nil
	}
	return &quarantineCauseError{cause: cause, err: err}
}

// QuarantineCauseFromError returns the cause tagged on err by a resolver, or
// metrics.QuarantineCauseOther when err carries no tag. It is the single place
// the cause is read back, and it must traverse the errors.Wrapf that Resolve
// applies per path.
func QuarantineCauseFromError(err error) metrics.QuarantineCause {
	var qce *quarantineCauseError
	if errors.As(err, &qce) {
		return qce.QuarantineCause()
	}
	return metrics.QuarantineCauseOther
}
```

3.2 Wrap each of the four `return r.fallback.Resolve(ctx, []string{path})` returns in `resolveOne` with `withQuarantineCause(..., <cause>)`, using the matching `metrics.QuarantineCause*` constant:

| Branch | Resolver-failure category | Quarantine cause |
|---|---|---|
| no three sides | `resolverFailureVaultAPINoSides` | `metrics.QuarantineCauseNoThreeSides` |
| merge request failed | `resolverFailureVaultAPIError` | `metrics.QuarantineCauseBreak` |
| declined | `resolverFailureVaultAPIDeclined` | `metrics.QuarantineCauseDeclined` |
| merged with no content | `resolverFailureVaultAPIEmptyContent` | `metrics.QuarantineCauseEmptyContent` |

The write-failure branch keeps its own `resolverFailureWrite` category and its fallback stays untagged (it becomes `other` downstream).

