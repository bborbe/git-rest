# Read claim commit messages in one batched git invocation

<summary>
- A claim-ref listing starts one `git cat-file --batch` process for the commit messages, regardless of how many refs match the prefix.
- The per-ref commit-message read is removed from both the mirror path and the hot part of the live path.
- The live-origin path falls back to one read per ref when the batch read fails, so a bad object costs a per-ref read instead of poisoning the whole batch, and the per-ref outcome is unchanged.
- The mirror path keeps its existing behavior: a failed read returns "not served" and the caller takes the live origin; it does not gain a per-item fallback.
- The existing fetch-batch flag is renamed so a failed message batch cannot be confused with a failed fetch batch.
- The batched method is added to the origin interface and its mock is regenerated, never hand-written.
- Cancellation still aborts the listing with a wrapped error and a nil result, checked on entry and at the top of every iteration.
- The listing returns exactly the same values, in the same order, as the golden captured in the previous prompt.
- Tests count real git processes through a `PATH` shim on both paths and at two prefix sizes, and cover the fallback and cancellation paths.
</summary>

<objective>
Make a claim-ref listing start a small, constant number of git processes by reading every matched commit message in one `git cat-file --batch` invocation, preserving ordering, per-path fallback semantics, and cancellation. This is the production fix for the per-ref process fan-out that makes the largest prefix miss its caller's deadline.
</objective>

## 2. Add the batched origin method (`pkg/git/claim_refs.go`)

2.1 Extend the `ClaimOrigin` interface (keep the existing `//counterfeiter:generate ...` annotation) with:

```go
ReadCommitMessages(ctx context.Context, shas []string) (map[string][]byte, error)
```

The map is keyed by the requested sha and each value is the commit message (the bytes after the first blank line, exactly what `ReadCommitMessage` returns today).

2.2 Implement it on `*gitOrigin`:

```go
func (o *gitOrigin) ReadCommitMessages(ctx context.Context, shas []string) (map[string][]byte, error)
```

- `len(shas) == 0` returns an empty non-nil map and nil error, without starting a process.
- Run one `git cat-file --batch` through `o.g.runCmdStdin`, with stdin equal to `strings.Join(shas, "\n") + "\n"`.
- On a runner error, return `nil, errors.Wrap(ctx, err, "git cat-file --batch")`.
- On success, delegate to `parseBatchCommitMessages`.

2.3 Add `parseBatchCommitMessages(ctx context.Context, shas []string, out []byte) (map[string][]byte, error)`:

- Read the output sequentially with a `bufio.Reader`, one object per requested sha, in the same order as `shas`.
- For each object, read a header line (up to `\n`). Split with `strings.Fields`. A valid header has exactly three fields: `<oid> <type> <size>`. Anything else — including git's `<input> missing` (two fields) and a non-`commit` type — is a batch failure: return `nil, errors.Errorf(ctx, "cat-file --batch: unexpected header %q", header)`.
- Parse the size with `strconv.Atoi`; a parse failure is a batch failure.
- Read exactly `size` bytes with `io.ReadFull`; a short read is a batch failure (truncated output).
- Read and discard the single `\n` git writes after each object's content; anything else is a batch failure.
- Key the map by `shas[i]` (the requested sha), not by the header's oid.
- Extract the message with the shared helper from requirement 2.4.

2.4 Add `extractCommitMessage(content []byte) []byte` and use it from BOTH `ReadCommitMessage` and `parseBatchCommitMessages` so the two paths cannot drift:

```go
func extractCommitMessage(content []byte) []byte {
    _, message, found := strings.Cut(string(content), "\n\n")
    if !found {
        return content
    }
    return []byte(message)
}
```

Rewrite `ReadCommitMessage` to call `extractCommitMessage(out)` and return its result.

## 3. Hoist the message read out of the single-ref helper

3.1 Add a batch reader beside `fetchClaimCommits` in `pkg/git/claim_refs.go`:

```go
// readClaimMessages reads every listed commit message in one git invocation.
// A failed batch is logged at debug only: the per-entry fallback owns the
// user-visible outcome.
func (g *git) readClaimMessages(
    ctx context.Context,
    matched []RemoteRef,
) (map[string][]byte, bool)
```

Build the sha slice from `matched`, call `g.origin.ReadCommitMessages`, and on error log with `slog.DebugContext` (message `"claim ref batch message read failed; falling back to per-sha reads"`, `"error", err`) and return `nil, false`. On success return the map and `true`.

3.2 Rename the existing fetch flag so the two batch outcomes are distinct. In `listClaimRefsLive` change `batchOK := g.fetchClaimCommits(ctx, matched)` to `fetchOK := g.fetchClaimCommits(ctx, matched)`. Rename the `batchOK` parameter of `readClaimRef` to `fetchOK` as well. Do not change `fetchClaimCommits` behavior or its return meaning.

3.3 Change `readClaimRef` to take the pre-read messages:

```go
func (g *git) readClaimRef(
    ctx context.Context,
    entry RemoteRef,
    fetchOK bool,
    messages map[string][]byte,
    batchOK bool,
) (ClaimRef, bool, error)
```

Body order:
- Start `claim := ClaimRef{Ref: entry.Ref, SHA: entry.SHA}`.
- `if !fetchOK` retry `g.origin.FetchCommits(ctx, []string{entry.SHA})` and on failure `return g.resolveFetchFailure(ctx, entry, err)` — unchanged.
- Look up `message, found := messages[entry.SHA]`.
- `if !batchOK` call `g.origin.ReadCommitMessage(ctx, entry.SHA)` here, wrapping a failure with `errors.Wrapf(ctx, err, "read claim commit %s", entry.SHA)` exactly as today, and set `found = true`.
- If `!found` (batch succeeded but the map has no entry), return `ClaimRef{}, false, errors.Errorf(ctx, "no commit message for %s", entry.SHA)`.
- Parse and populate the claim exactly as today.

This is the ONLY surviving `origin.ReadCommitMessage(` call site; it must sit inside the `!batchOK` branch.

3.4 In `listClaimRefsLive`, after `fetchOK := g.fetchClaimCommits(...)`, add `messages, batchOK := g.readClaimMessages(ctx, matched)` and pass both into `readClaimRef`. Keep the existing top-of-loop cancellation `select` exactly as it is.
